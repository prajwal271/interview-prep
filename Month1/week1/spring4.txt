Constructor injection is the recommended approach because it makes dependencies explicit through the constructor signature, allows fields to be final which prevents accidental reassignment and ensures thread safety, and makes classes testable without a Spring context — you just pass mock objects to the constructor. Field injection hides dependencies and is only injectable via Spring's reflection, making unit testing impossible without a full Spring context. In Spring Boot 4.3+, if a class has exactly one constructor, @Autowired is not needed — Spring detects it automatically. Lombok's @RequiredArgsConstructor generates the constructor for all final fields, eliminating boilerplate while keeping all the benefits of constructor injection.

@Value Limitations — When It Breaks Down

Works fine for 2-3 properties. But what about 10 properties? 10 separate @Value annotations. No IDE autocompletion on property names. Typo in "${library.nme}" → fails at RUNTIME not compile time. Hard to test — must mock each property separately. Hard to group — scattered across multiple services

Spring auto-converts the string value to the field's type — int, boolean, double, arrays. You can provide a default with a colon: `
property.key‘syntax.Springauto−convertsthestringvaluetothefield′stype—int,boolean,double,arrays.Youcanprovideadefaultwithacolon:‘{key:default}`. Validation — The Killer Feature
This is what makes @ConfigurationProperties truly powerful over @Value

@ConfigurationProperties(prefix = "library")
@Component
@Data
@Validated  // enable validation on config properties
public class LibraryProperties {

    @NotBlank(message = "Library name cannot be empty")
    private String name;

    @Min(value = 1, message = "Must allow at least 1 book")
    @Max(value = 20, message = "Cannot allow more than 20 books")
    private int maxBooksPerUser;

    @Email(message = "Admin email must be valid")
    private String adminEmail;

    @DecimalMin("0.0")
    private double finePerDay;
}

`@ConfigurationProperties` binds a group of related properties from `application.yml` to a single Java class using a prefix. Unlike `@Value` which handles one property at a time, `@ConfigurationProperties` gives you a typed object with IDE autocompletion, relaxed binding between kebab-case YAML keys and camelCase Java fields, support for nested objects and lists, and validation via `@Validated`. This makes it far superior for managing multiple related properties — the config is grouped in one place, testable by just instantiating the class, and errors are caught at startup not runtime.

								What is Dynamic Programming?
DP : If I already calculated something — remember it. Never calculate it twice.

    You are climbing a staircase with n steps.
    Each time you can climb 1 or 2 steps.
    How many distinct ways can you climb to the top?
    n=1 → 1 way:  (1)
    n=2 → 2 ways: (1+1), (2)
    n=3 → 3 ways: (1+1+1), (1+2), (2+1)
    n=4 → 5 ways: (1+1+1+1), (1+1+2), (1+2+1), (2+1+1), (2+2)
    n=5 → 8 ways

1,1,2,3,5,8 ---> This is a Fibonacci series sum of the previous 2 will give the current number , then apply this idea only to find the no of ways to climb 5 stairs I need to know no of ways to climb 3 stairs and 4 stairs 

The Naive Approach — Recursion
"To find ways(5), I need ways(4) and ways(3)"
"To find ways(4), I need ways(3) and ways(2)"
"To find ways(3), I need ways(2) and ways(1)"

In Java, ^ is the bitwise XOR (exclusive OR) operator. It compares each bit of two operands and returns 1 if the bits are different, and 0 if they are the same.

int a = 5;  // 0101 in binary
int b = 3;  // 0011 in binary

int result = a ^ b; // 0110 = 6
